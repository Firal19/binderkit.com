# binderkit.com

The Binderkit landing page. Binder setup for care homes.

One HTML page, one stylesheet, one 6 kB script, no framework and no runtime
dependencies. `node build.mjs` writes `dist/` and `dist/` is the site.

## Run it

```sh
node build.mjs          # → dist/
node tools/check.mjs    # what has to be true of the built bytes
node tools/serve.mjs    # http://localhost:4321
```

Two local tools need a browser and are not part of the build:

```sh
node tools/icons.mjs    # the app icons and the social card → src/assets/raster/
node tools/shots.mjs    # every width, light and dark → review/
```

Both find Playwright on their own, or take `PLAYWRIGHT=/path/to/playwright`.

## What is where

| | |
|---|---|
| `src/data/brand.js` | the family, as the system document states it |
| `src/data/page.js` | this page, as data — one spine, no HTML |
| `src/data/states.js` | the four words this product owns for its own states |
| `src/render/pages/<id>.js` | this page, its own composition |
| `src/css/pages/<id>.css` | this page, its own face — fonts, palette, layout |
| `src/render/shared.js` | the few pieces every page shares: the form, the FAQ, the byline |
| `src/render/instruments.js` | the product surfaces the page shows, rendered in HTML |
| `src/marks.js` | the five marks, three bodies each |
| `src/css/faces.css` | the face package, generated by the system board |
| `src/css/base.css` | the reset, the form and the small “By Providerhub Oregon” lockup |
| `api/waitlist.js` | the one endpoint |
| `convex/` | the one table behind it |

The instruments on the page — the phone, the desktop, the printed sheet — are the product’s own screens rendered in HTML; `src/css/faces.css` is generated by the system board at [bydesign.providerhub.us](https://bydesign.providerhub.us) and gives them their values. The page around them is this product’s own design and nobody else’s.

## The waitlist

`POST /api/waitlist` takes `{ email, track, houses, product }`, checks them,
and writes one row to Convex. Two environment variables on the Vercel project:

| | |
|---|---|
| `CONVEX_URL` | `https://<deployment>.convex.cloud` — required |
| `WAITLIST_FORWARD` | an address to copy each row to — optional |
| `RESEND_API_KEY` | needed only with `WAITLIST_FORWARD` |

With `CONVEX_URL` unset the endpoint answers 503 and the page says so rather
than pretending the row was kept.

Read the list with the `waitlist:list` query, which wants the `WAITLIST_KEY`
set in the Convex environment.

## Deploy

```sh
npx convex deploy -y     # the one table
vercel --prod            # the page
```
